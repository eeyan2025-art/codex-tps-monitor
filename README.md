# Codex TPS Monitor

> 面向 Codex Windows 桌面版的轻量本地 TPS 监视器。以“对话 → 主会话/子代理 → 模型”的方式展示最新估算 TPS 和平均估算 TPS。

**当前版本：V4（Windows PowerShell 固定面板版，含模型切换与排序修正）**

**状态：可试用，尚未在各种真实多会话/多子代理场景中充分验证。**

## 项目解决什么问题

Codex Windows 桌面版没有在常规界面直接展示每个对话、各模型的输出速度。这个工具不修改 Codex，也不接管请求，仅从本机已有会话日志中提取 Token 统计数据和时间戳，以便对比模型响应速度。

## 效果预览

以下数值及模型名**纯属示意**，不代表实际测量或当前支持特定型号：

```text
Codex TPS | session / model / subagent | Ctrl+C to exit
Local read-only | Scan + 3s pause | TPS = estimate from log events

Session 1 [a31f82c0]  project-A
  main           | model-A | TPS ~185.6 | Avg ~172.3 | recent | n=12
  agent b62d193a | model-B | TPS ~96.3  | Avg ~103.7 | recent | n=8

Session 2 [c98e120d]  project-B
  main           | model-A | TPS ~203.1 | Avg ~191.8 | idle | n=6
```

面板在每次扫描完成后等待 **3 秒**，再在原位置重新绘制数字，不会不断追加历史行。新发现的会话/子代理/模型会增加展示条目；超出活动窗口的日志可能从列表消失。`recent` / `idle` 是根据最近有效统计样本时间推断的状态，**不是** Codex 官方的“运行中”信号。

## 主要功能

- **对话分组：** 按本地日志提供的会话标识及父子关系尝试归并对话。
- **区分主会话和子代理：** 主会话显示为 `main`，检测到的子代理标注 `agent` 和简短 ID。
- **按模型分别统计：** 从 `turn_context.model` 等本地事件读取模型名称；模型标识缺失时显示 `unknown`。
- **最新 TPS：** 展示该会话/模型最近一个有效日志样本的估算速度。
- **平均 TPS：** 展示该会话/模型所有有效样本的加权平均速度。
- **固定面板：** 刷新时更新原有内容，而非持续打印新行。
- **纯本地只读：** 不访问 Codex IPC，不修改客户端，不主动发送网络请求，也没有额外 Python 或第三方库依赖。

## 如何安装和使用（Windows 小白版）

1. 在本仓库页面选择 **Code → Download ZIP**，下载并解压。
2. 确保文件夹中同时有 `start-monitor.bat` 和 `monitor.ps1`。
3. **双击 `start-monitor.bat`**，会出现一个 PowerShell 监视窗口。
4. 照常使用 Codex Windows 桌面版；有可用日志后面板会显示记录。
5. 用完后按 **Ctrl+C** 或直接关闭窗口。

不需要安装 Python，不需要输入命令，不需要 API Key。请不要把两个文件分开放置。

## 工作原理

```text
Codex Windows 客户端（照常运行）
     ↓ 写入本机会话 JSONL 日志
%USERPROFILE%\.codex\sessions\...\*.jsonl
     ↓ PowerShell 以共享读取模式读取
解析 session_meta / turn_context / token_count 等事件
     ↓
按会话、子代理和模型整理有效样本
     ↓
计算最新估算 TPS、平均估算 TPS
     ↓
每次全量重扫完成后等待 3 秒，再刷新固定控制台面板
```

- **技术栈：** Windows 批处理 (`.bat`) + Windows 自带的 PowerShell (`.ps1`) + .NET 文件与控制台 API。
- **默认日志位置：** `%USERPROFILE%\.codex\sessions`。若存在 `CODEX_HOME` 环境变量，则优先读取该目录下的 `sessions`。
- **文件占用处理：** 使用 `.NET FileStream` 并启用 `FileShare.ReadWrite | FileShare.Delete`，尽量避免 Codex 正在写日志时产生的“被另一进程使用”异常。
- **扫描范围：** 最近 **15 分钟内被修改**的日志文件，最多读取最近修改的 **80 个**；并非完整历史数据统计。
- **刷新间隔：** 每次全量读取选中文件完成后再等待 3 秒，因此实际间隔是扫描耗时加 3 秒，不是严格的 3 秒周期。

## TPS 如何计算

代码使用日志中的 `token_count` 事件及其 `info.last_token_usage.output_tokens` 字段，读取输出 Token 数和事件时间戳。

**最新估算 TPS** = 最近一个有效样本的输出 Token 数 ÷ 该样本与前一条相邻、同模型 Token 统计事件的时间间隔。

**平均估算 TPS** = 该会话/模型的有效样本输出 Token 总和 ÷ 对应有效时间间隔总和。

有效时间间隔暂限定在 **0.25 秒至 600 秒**，且要求输出 Token 数大于零。识别到模型切换时立即清空前一事件，即使中间模型没有 Token 事件，也不跨越切换间隔计算。

**重要限制：** 事件时间间隔不等同于纯模型解码时间，可能包含思考、网络、工具等待、日志写入等开销。因此两个数字都只是“基于日志事件的估算 TPS”，**不是逐 Token 实时生成速度，也不能用于严格模型性能基准测试**。

## 多会话与子代理识别

每个 JSONL 通常对应一个会话文件。脚本尝试从 `session_meta` 中读取 `id`、`parent_thread_id`、`session_id` 和 `source.subagent.thread_spawn.parent_thread_id` 等信息确定父子归属，并通过 `cwd` 推导项目文件夹名称。

当前只根据文件中的直接父级或会话标识归组，不递归查找祖先。嵌套子代理可能被分到不同组，缺少主会话文件时可能显示 `project unknown`。

这些字段会随 Codex 版本和不同执行模式变化。**如果日志没有记录可用的父子关联，子代理可能被列为独立会话，或者无法完整聚合；脚本不会读取 Codex 的内部 IPC 来补齐信息。** 同一模型在不同会话下会分别计算，无法识别的模型显示 `unknown`。

## 安全和隐私边界

- 脚本以只读方式打开本地日志，**不修改** Codex 的会话文件或设置。
- 不使用网络请求、API Key、代理、注入、Hook 或内部 IPC。
- 没有安装服务、开机自启或驻留程序；关闭窗口即停止。
- `start-monitor.bat` 使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ...` **仅启动该次脚本**；这不等于修改全系统的永久执行策略，但运行脚本前仍应检查文件内容和来源。
- **日志可能含有代码、提示词、文件路径或其他敏感内容**。监视器会读取这些文件中的行以筛选相关事件，虽然不会将它们发到网络上，仍须保护本地机器和脚本来源。

本工具的设计风险相对低，但**不能据此保证被 OpenAI 官方认可、不会触发任何风控，或者保证安全性已获第三方审计**。

## 已知局限

1. **不是严格实时 TPS。** 每次扫描完成后暂停 3 秒，新的 TPS 依赖 Codex 写出下一条可解析的 Token 统计事件；日志较大时刷新会更慢。
2. **可能含等待时间。** 实测值往往低于模型纯生成阶段的速度。
3. **活动列表不是运行进程列表。** 最近修改的文件可能已停止执行，仍会短暂显示；超过 15 分钟可能消失。
4. **父子代理关系依赖日志字段。** 并非所有版本都能准确归组。
5. **模型标记可能不全。** 字段缺失时显示 `unknown`，模型切换附近的统计样本也可能无法完整归因。
6. **平均值仅覆盖脚本扫描到的有效样本。** 不是一个模型的全球平均，也不一定是完整对话生命周期平均。
7. **终端窗口大小有限。** 会话/模型条目过多时，固定面板的后几行可能被窗口高度截断。
8. **重复用量快照可能重复计数。** 当前沿用每条事件的 `last_token_usage.output_tokens`，不计算累计值的差分，也不能可靠识别不同时间重复记录的同一用量；相同 Token 数也可能来自两个不同请求，因此没有按数值去重。
9. **未完成完整实机兼容性测试。** 已提供覆盖解析、统计和排序的合成测试，但本次本机启动测试被 PowerShell 授权检查阻止，尚未取得运行结果。未用真实会话验证固定面板、Ctrl+C、日志轮转、共享读取竞争及多层子代理归组。不保证所有 Codex Windows 版本和日志格式均正常工作。

## 常见问题

**Q：同时运行两个 Codex 对话，会显示合计 TPS 吗？**

A：不会。按可识别的对话和模型分开统计；当前版本没有提供跨对话的合计 TPS。

**Q：一个对话里两个模型或多个子代理呢？**

A：脚本尽量按父子关系放到同一对话下，并按每个子代理与模型分别展示；若日志缺失关联字段则可能分组失败。

**Q：没有数据怎么办？**

A：先在 Codex 中正常执行一段任务，确认本机 `sessions` 下有近期 `.jsonl` 日志及足够的 `token_count` 事件。只出现一个有效事件时还不能构成时间间隔。权限不足时不要以管理员身份或修改权限来绕过限制；本工具不会替你获取日志访问权限。

**Q：一直是 `idle` 是不是坏了？**

A：不一定。它只是表示最近有效 TPS 样本距离当前时间较久，不能反推真实任务状态。

**Q：需要一直开着吗？**

A：只有想查看面板时才需要运行；关闭监视器不会影响 Codex。
